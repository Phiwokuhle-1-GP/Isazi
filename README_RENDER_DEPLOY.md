# Isazi Herbal Shop — Render deployment (Client Portal V4.2)

This is the *project management/client review portal* with a public construction page, not a live payment-taking e-commerce store.

## Recommended architecture

- **Service:** Render Python web service (paid compute plan, e.g. 0.5c-512mb)
- **Database:** Current SQLite project database on a **persistent Render disk** at `/var/data/isazi.sqlite3`
- **Web server:** Waitress WSGI, listening on Render-provided `$PORT`
- **HTTPS:** Render terminates TLS; `ISAZI_HTTPS=1` sets secure cookies
- **Secret key:** generated by Render from `render.yaml`, never in source code
- **First administrator:** `owner`, with a password you enter privately when creating the Blueprint
- **Domain:** optional later; Render assigns a `*.onrender.com` address

**Important:** This config requires a **paid Render service + disk**. Rendering the user accounts, client comments and plan history to Render's Free filesystem would cause data loss on redeployment, restart or spin-down. Do **not** change `plan` to `free` without migrating state to permanent storage. Render Postgres is not currently supported by this SQLite-specific code.

## 1. Before deploying: backup the local database

On your Windows PC, close Flask (Ctrl+C), then in PowerShell:

```powershell
cd "$HOME\Downloads\isazi_ecs_agile_manager"
Copy-Item '.\instance\isazi.sqlite3' '.\instance\isazi.sqlite3.before-render.bak' -ErrorAction SilentlyContinue
```

Your **local owner account and comments are not automatically moved** to the Render database. The deploy initially creates a fresh owner account unless you migrate the SQLite file using SCP (see below). Never commit the `instance` directory or the `.env` file to GitHub.

## 2. Create a dedicated, empty GitHub repository

Create a **new repository** called e.g. `isazi-herbal-shop-portal` on GitHub. Do *not* put Isazi project files into the ECS company website repository. Copy/extract the folder containing `render.yaml`, `app.py`, `templates/`, `static/`, `state.py`, `status_report.py` to your local machine. From PowerShell in that folder:

```powershell
git init -b main
git add .
git commit -m "Prepare Isazi client portal V4.2 for Render"
git remote add origin https://github.com/YOUR_GITHUB_USER/isazi-herbal-shop-portal.git
git push -u origin main
```

Replace `YOUR_GITHUB_USER` with your own GitHub username. Authenticate through GitHub's normal desktop or browser flow. The included `.gitignore` excludes local SQLite and secrets. Do not use `--force`.

Or, for a **new, empty** GitHub repo, you can use the included guided PowerShell uploader in the extracted folder:

```powershell
powershell -ExecutionPolicy Bypass -File ".\PUSH_GITHUB_WINDOWS.ps1" -RepoUrl "https://github.com/YOUR_GITHUB_USER/isazi-herbal-shop-portal.git"
```

The script refuses to overwrite a repo already present in the extracted folder and never uses a force push.

## 3. Create a Render Blueprint

Open [Render Dashboard](https://dashboard.render.com/), select **New > Blueprint**, connect the new repository, then follow the configuration detected in `render.yaml`.

- Verify the service is **paid** (not Free), with a persistent **1 GB disk** at `/var/data`.
- When prompted for `ISAZI_BOOTSTRAP_OWNER_PASSWORD`, enter a long unique password (at least 12 characters) **in Render**, not in GitHub/ChatGPT.
- Render generates `ISAZI_SECRET_KEY`; keep it unchanged on redeploys.
- Wait for the service to build and become healthy at `/health`.
- Use `https://YOUR-SERVICE.onrender.com/login` with username `owner` and your private password.
- After first successful login, remove `ISAZI_BOOTSTRAP_OWNER_PASSWORD` from Render's service Environment settings. This is no longer required because the owner exists on disk.
- In the owner dashboard, create separate client **viewer** accounts. Never share the owner login with clients.

The first public page (`/`) is only a construction notice. Private pages require login:

- `/owner` — owner dashboard
- `/client/progress` — status steps
- `/client/scope` — scope-only agreement (no project price)
- `/client/designs` — storefront concept gallery
- `/client/status-report.pdf` — status PDF (authenticated)
- `/health` — deployment health check

**Security:** Do not publish a client login until testing. Keep the workspace protected and use unique passwords. Production launch should also include dependency security review, backups and an operational support plan.

## 4. Migrating your existing SQLite data (optional but important)

A new deploy creates a **new database** (seed state and a fresh owner account), so previous local client notes and passwords do not automatically appear. To preserve them:

1. Back up local `instance/isazi.sqlite3` with Flask **stopped**. Include the `-wal` file if SQLite was left in WAL mode; safer is to use SQLite's online backup API.
2. Obtain the exact SSH/SCP host from the **new service** in Render. Render supports transfer to a persistent disk using `scp -s` once SSH is configured.
3. Schedule a brief maintenance window, transfer the backup SQLite database to `/var/data/isazi.sqlite3`, and restart the Render service so it loads the transferred data. Do not overwrite a database with newer remote client feedback.
4. Verify user login, current version and historical revisions after restart. Your original login password remains the one stored in the copied SQLite file.

Example: `scp -s C:\path\to\isazi.sqlite3 YOUR_RENDER_SSH_HOST:/var/data/isazi.sqlite3` — the host is provided in your own Render service settings; **do not guess it**. Render's official transfer guide: https://render.com/docs/disks

## 5. Updating the deployed site

Edit and test locally, commit to GitHub, and push:

```powershell
git add .
git commit -m "Update Isazi client portal"
git push origin main
```

Render will redeploy connected commits automatically (unless auto-deploy is turned off). The attached `/var/data` disk persists project data across deployments. **Do not rotate `ISAZI_SECRET_KEY` unintentionally**; doing so logs users out.

## 6. Testing

Run locally after installing `requirements.txt`:

```powershell
python -m unittest discover -s tests -v
python deploy_bootstrap.py
```

`deploy_bootstrap.py` refuses to create an owner if `ISAZI_BOOTSTRAP_OWNER_PASSWORD` is not set. It **never** overwrites an existing account. For a test environment you may temporarily set a private password in your terminal using `$env:ISAZI_BOOTSTRAP_OWNER_PASSWORD = Read-Host 'Owner password'` without committing it.

You can test the Render production WSGI entrypoint locally using `waitress-serve --host=127.0.0.1 --port=5000 wsgi:app` once the SQLite database has an owner account.
